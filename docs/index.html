จากหน้าว่าง
ถึงลิงก์ที่แชร์ได้

คู่มือนี้พาคุณตั้งแต่สร้างเซลเพจแรก เชื่อม GitHub repository ของตัวเอง ไปจนถึงการ deploy บน Vercel — ทุกขั้นตอนใช้เวลาไม่ถึง 10 นาที

ภาพรวม เริ่มต้นใช้งาน เชื่อม GitHub Deploy บน Vercel แก้ไขและปรับแต่ง โครงสร้างข้อมูล ความปลอดภัย แก้ปัญหาเบื้องต้น

ภาพรวม

PIXSALE เป็นเว็บแอปแบบ static ทั้งหมด — ไม่มีเซิร์ฟเวอร์หลังบ้าน ไม่มีฐานข้อมูลกลาง ข้อมูลของแต่ละร้านอยู่ในสองที่:

  • เบราว์เซอร์ของคุณ — สำเนาทำงานที่แก้ไขได้ทันที (localStorage)
  • GitHub repository ของคุณ — ไฟล์ JSON จริงที่ใช้เผยแพร่และสำรองข้อมูล

เมื่อ deploy บน Vercel ตัวเว็บจะอ่านไฟล์จาก data/pages/*.json ในโปรเจกต์ และสามารถอ่านเวอร์ชันล่าสุดจาก GitHub ผ่าน raw URL ได้โดยไม่ต้อง deploy ใหม่ทุกครั้งที่แก้หน้า

สิ่งที่ต้องมี: บัญชี GitHub (ฟรี) และบัญชี Vercel (ฟรี) — ไม่ต้องใช้บัตรเครดิตสำหรับการเริ่มต้น

เริ่มต้นใช้งาน

  1. เปิด PIXSALE Studio — ระบบจะสร้างข้อมูลตัวอย่าง 3 หน้าให้อัตโนมัติ
  2. กด สร้างเซลเพจ เลือกเทมเพลต แล้วตั้งชื่อและ slug
  3. แก้ข้อความ เพิ่มบล็อก และเลือกสีแบรนด์ในแท็บ ธีม
  4. กด บันทึก — ถ้ายังไม่เชื่อม GitHub ข้อมูลจะอยู่ในเบราว์เซอร์เครื่องนี้
  5. เปิดสวิตช์ เผยแพร่ เมื่อพร้อมให้ลูกค้าเห็น
หมายเหตุ: การเผยแพร่ในเครื่องจะทำให้หน้าแสดงที่ /p/?id=slug บนเครื่องของคุณเท่านั้น หากต้องการลิงก์จริงบนอินเทอร์เน็ต ต้อง deploy ขึ้น Vercel ก่อน

เชื่อม GitHub

การเชื่อม GitHub ทำให้ทุกหน้าเก็บเป็นไฟล์ JSON ใน repo ของคุณ และมีประวัติการแก้ไขย้อนหลังทุกครั้ง

1. สร้าง repository

  1. ไปที่ github.com/new
  2. ตั้งชื่อ pixsale-lnwads-tiktok
  3. เลือก Public — จำเป็นสำหรับให้หน้าเว็บอ่านข้อมูลโดยไม่ต้องใช้ token
  4. ไม่ต้องติ๊ก README, .gitignore หรือ license
  5. กด Create repository

2. สร้าง fine-grained token

  1. ไปที่ Settings → Developer settings → Personal access tokens → Fine-grained tokens
  2. ตั้งชื่อ เช่น pixsale-studio และเลือกวันหมดอายุ
  3. ที่ Repository access เลือก Only select repositories แล้วเลือก repo ที่สร้างไว้
  4. ที่ Permissions → Repository permissions → Contents เลือก Read and write
  5. กด Generate token แล้วคัดลอกค่า github_pat_…
สำคัญ: token ถูกเก็บใน localStorage ของเบราว์เซอร์คุณเท่านั้น ไม่ถูกเขียนลงไฟล์ ไม่ถูก commit และไม่ถูกส่งไปยังเซิร์ฟเวอร์ใด ๆ นอกจาก api.github.com

3. เชื่อมในแอป

  1. เปิด ตั้งค่า → GitHub repository
  2. กรอก owner (ชื่อผู้ใช้ GitHub), repo, branch (main) และ token
  3. กด ทดสอบการเชื่อมต่อ แล้วจึงกด เชื่อมต่อและบันทึก
  4. ไปที่ ซิงก์ข้อมูล กด อัปโหลดทุกหน้าขึ้น GitHub

ไฟล์จะถูกเขียนที่:

data/site.json
data/pages/{slug}.json

Deploy บน Vercel

โปรเจกต์นี้เป็น static site ล้วน ไม่มีขั้นตอน build จึงใช้เวลาน้อยกว่า 1 นาที

  1. ไปที่ vercel.com/new แล้วเข้าสู่ระบบด้วย GitHub
  2. เลือก repo pixsale-lnwads-tiktok → Import
  3. Framework Preset: Other · Build Command: เว้นว่าง · Output Directory: .
  4. กด Deploy — จะได้ URL เช่น pixsale-lnwads-tiktok.vercel.app
  5. ทุกครั้งที่ push ไฟล์ใหม่ Vercel จะ deploy ให้อัตโนมัติ

ผูกโดเมนของคุณเอง

ใน Vercel ไปที่ Project → Settings → Domains แล้วเพิ่มโดเมน จากนั้นตั้งค่า DNS ตามที่ Vercel แนะนำ (A record หรือ CNAME)

หลัง deploy: เปิด /app/settings.html บนโดเมนจริง แล้วเชื่อม GitHub อีกครั้งหากต้องการให้หน้านี้เขียนข้อมูลกลับ repo จากอุปกรณ์อื่นได้ — token ไม่ถูกส่งต่อระหว่างเบราว์เซอร์

แก้ไขและปรับแต่ง

แก้ข้อความและราคา

ทำได้ในหน้า แก้ไข ทั้งหมด — เลือกบล็อกทางซ้าย แก้ในแท็บ “เนื้อหา” พรีวิวทางขวาจะอัปเดตทันที

เปลี่ยนสี ฟอนต์ โหมดสว่าง/มืด

แท็บ ธีม มีสีหลัก 6 สีพร้อมใช้ และช่องกำหนดสีเอง (HEX) เปลี่ยนโหมดเป็น dark ได้ทั้งหน้า โดยสีพื้นและตัวอักษรจะปรับอัตโนมัติ

เพิ่มบล็อกใหม่

บล็อกที่มีให้ใช้: ฮีโร่, สินค้า, จุดเด่น, แกลเลอรี, รีวิว, นับถอยหลัง, คำถาม, ลิงก์, ปิดการขาย และฟุตเตอร์ — ทั้งหมดเรียงลำดับได้ด้วยปุ่มลูกศรในรายการบล็อก

แก้โค้ดหรือสไตล์

  • สีและฟอนต์ทั้งระบบ: assets/css/tokens.css
  • หน้าตาเซลเพจ: assets/css/page.css
  • หน้าแบรนด์: assets/css/site.css
  • ตัวเรนเดอร์บล็อก: assets/js/render.js

โครงสร้างข้อมูล

หนึ่งหน้าเท่ากับหนึ่งไฟล์ JSON ตัวอย่าง:

{
  "id": "tiktok-shop-starter-kit",
  "slug": "tiktok-shop-starter-kit",
  "title": "TikTok Shop Starter Kit",
  "brand": "PIXSALE Studio",
  "status": "published",
  "theme": { "accent": "#d91e36", "mode": "light", "font": "sans" },
  "seo": { "title": "…", "description": "…" },
  "stats": { "views": 12480, "clicks": 842 },
  "blocks": [
    { "id": "hero_x1", "type": "hero", "props": { "title": "…" } },
    { "id": "prod_x2", "type": "product", "props": { "price": 690 } }
  ]
}

ฟิลด์ที่สำคัญ:

  • slug — ใช้ใน URL และเป็นชื่อไฟล์ ต้องเป็น a-z, 0-9 และ -
  • status — published หรือ draft
  • theme.accent — สีหลักของหน้านั้น
  • blocks[].props — เนื้อหาของแต่ละบล็อก

ความปลอดภัย

  • ใช้ fine-grained token ที่จำกัดเฉพาะ repo เดียว และสิทธิ์ Contents: Read and write
  • ตั้งวันหมดอายุ token และหมุนเวียนเป็นประจำ
  • อย่า commit token ลงไฟล์หรือ screenshot หน้า settings
  • หาก token รั่ว ให้ revoke ที่ GitHub แล้วสร้างใหม่ทันที
  • ข้อมูลหน้าเว็บเป็น HTML/JSON สาธารณะ — อย่าใส่ข้อมูลลูกค้าที่ละเอียดอ่อนในเซลเพจ

แก้ปัญหาเบื้องต้น

เชื่อมต่อไม่ได้ (401 / 403)

ตรวจว่า token ยังไม่หมดอายุ และให้สิทธิ์ Contents: Read and write กับ repo นั้นจริง ๆ

บันทึกแล้วแต่ไฟล์ไม่ขึ้น GitHub

ตรวจ branch ว่าเป็น main หรือชื่อที่ repo ใช้จริง และ path เริ่มที่ data — ถ้า repo ว่าง ระบบจะสร้างไฟล์แรกให้อัตโนมัติ

หน้าเว็บขึ้น 404

ตรวจว่า status เป็น published และ slug ใน URL ตรงกับชื่อไฟล์ใน data/pages
